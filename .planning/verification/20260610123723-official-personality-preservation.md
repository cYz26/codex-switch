# Verification: official personality preservation

## Scope

Internal Codex Desktop wrapper shared-config foldback previously rewrote the
official home `config.toml` from a shared-only base. That removed
profile-specific official runtime settings such as `model` and `personality`,
so a Personalization personality change made in official mode could revert
after switching to internal and back.

## Change

- Added a regression test for internal Desktop wrapper startup preserving
  official `model` and `personality` while still folding shared internal
  app-home settings back into the official home.
- Updated the wrapper generated by `scripts/codex_switch_app_wrapper.py` to use
  the existing official runtime config as the merge base and overlay only
  shared settings from the internal app home.
- Recorded the behavior in the active OpenSpec delta, README, tasks ledger, and
  workflow state.

## Red / Green Evidence

```bash
python3 scripts/test_codex_profile_switch.py CodexProfileSwitchTests.test_internal_desktop_wrapper_preserves_official_personality
```

Result before fix: failed because the wrapper rewrote official `config.toml`
to `[features]` plus the shared MCP server only, dropping
`model = "official-runtime"` and `personality = "friendly"`.

Result after fix: passed.
